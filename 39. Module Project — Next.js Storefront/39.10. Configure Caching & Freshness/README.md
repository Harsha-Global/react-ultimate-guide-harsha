# Configure Caching & Freshness

The completed application is the exact source demonstrated in the video.

- Starter/shopfront-next: the ShopFront app as completed in the previous lecture.
- Support Files: the cached catalog reader (lib/catalogCache.ts), the local write guard (lib/demoWriteAccess.ts), the stock input parser and its tests (lib/stockInput.ts, tests/stockInput.test.mjs), the stock Server Action (app/actions/stock.ts), the stock editor and form (components/StockEditor.tsx, components/StockForm.tsx), the updated sample API and fixture switch (scripts) and .env.local.example, copied into the project in the video.
- Completed/shopfront-next: the app at the end of this lecture. Keep it for the next lecture.

Cached public reads and an accepted inventory change, as the client's change request in the Next Storefront - v2 design asks: Cache Components and partial prefetching enabled in next.config.ts; readStorefront switched to the tagged cached reader (readCachedCatalog); and components/InventoryDemo.tsx, which shows the supplied stock editor on the collection page only when COURSE_ALLOW_WRITES is local-fixture and the site is opened on this computer. The supplied action validates the value, sends it to the sample API and, once the API accepts it, expires the catalog tag (updateTag) and refreshes the page.

## Run

Copy the shopfront-next folder into your React workspace (for example C:\react\shopfront-next; no folder anywhere in the path may contain the & character) and open it in VS Code. Stop any other app using ports 3000 or 5211 first. In a first terminal run `npm ci` (the first installation needs registry access), then `npm run api:reset` and `npm run api`: the local sample catalog API listens on http://127.0.0.1:5211 (http://127.0.0.1:5211/health reports its status). Copy .env.local.example to .env.local (COURSE_ALLOW_WRITES=local-fixture shows the local inventory editor on the collection when the site is opened on this computer; it is a teaching switch, not authentication, and never belongs on a public deployment). In a second terminal run `npm run dev -- --port 3000` and open http://localhost:3000 (the npm scripts bind 127.0.0.1; keep using localhost, as 127.0.0.1 is a different browser-storage origin for the shortlist). Run the fixture commands (`npm run api:slow`, `npm run api:error`, `npm run api:ready`, `npm run api:reset`) in a third terminal in the same folder as the running API. To check a production build, stop the development server with Ctrl+C (keep the API running: the build reads the catalog from it), then run `npm test`, `npm run typecheck`, `npm run build` and `npm start -- --port 3000`. Finish with `npm run api:reset` and stop both processes.

## Try it

In production (`npm run api:reset` in the API's folder, then `npm run build` and `npm start -- --port 3000`), /catalog shows the lamp with 12 and Review the lamp stock: save 7. The API accepted the stock update, and the card, /categories/workspace, the overlay and a reload of the product address all show 7. Run `node scripts/api-mode.mjs reject` and save 9: the rejection message appears and the stock stays 7; run `node scripts/api-mode.mjs ready` and save again. To check the switch, stop Next and start the same build with writes disabled (PowerShell: `$env:COURSE_ALLOW_WRITES="disabled"`, then `npm start -- --port 3000`; macOS/Linux: `COURSE_ALLOW_WRITES=disabled npm start -- --port 3000`): the editor is gone, and a stock request kept from the browser's Network panel and sent again answers Local sample writes are disabled. Afterwards remove the variable (`Remove-Item Env:COURSE_ALLOW_WRITES`) and run `npm run api:reset`.
