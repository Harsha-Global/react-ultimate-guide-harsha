# Admin Workspace — TanStack Query for the catalog, Zustand for display preferences

The Zustand workspace project loads its catalog through TanStack Query 5.104.1 (installed with --save-exact). src/queryClient.ts creates one QueryClient at module level with retry and refetchOnWindowFocus turned off for this teaching project; src/main.tsx wraps PreferenceBoundary in QueryClientProvider inside the existing adapters. src/useProducts.ts calls useQuery with the key ["catalog", query] (the complete query string from the URL choices), passes the abort signal and query to getProducts and keeps a result fresh for 30 seconds (staleTime); it returns the ready / loading / error state plus refreshing and refreshFailed for a cache entry that already has data, retry (refetch) and refreshCatalog (invalidates the ["catalog"] key family). src/App.tsx refreshes the catalog after an accepted save, shows a status while a cached view refreshes and an alert with Retry refresh when a refresh fails, and keeps the first-load error with Retry catalog. Display preferences stay in the Zustand store; no product rows are copied into it.

## Run

Copy the project into your React workspace (for example C:\react\zustand-workspace) and open it in VS Code. In one terminal run `npm ci`, then `npm run api` (the local catalog service on http://127.0.0.1:5191, in memory: a restart restores the four sample products). In a second terminal run `npm run dev` and open http://127.0.0.1:5190 (stop any other app using ports 5190 or 5191 first, and use the same 127.0.0.1 address throughout: localhost is a different browser-storage origin). Validate with `npm run lint` and `npm run build`.
