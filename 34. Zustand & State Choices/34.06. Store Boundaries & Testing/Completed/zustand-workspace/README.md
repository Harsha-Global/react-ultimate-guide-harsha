# Admin Workspace — a reusable store factory with isolated store tests

The Zustand workspace project creates its store through a factory. src/workspaceStore.ts exports createWorkspaceStore(storage: StateStorage, health = createStorageHealth()): it returns a new persisted store (create<WorkspaceState>()(persist(...))) that uses the received storage adapter in createJSONStorage and reports a restore error through the received health object; the preferences, actions, version 1, migration and validated merge are unchanged. The browser keeps one module-level instance: useWorkspaceStore = createWorkspaceStore(browserPreferenceStorage, storageHealth), so the components keep their imports. tests/memory-storage.mjs returns a fresh Map-backed adapter on each call, and tests/workspace.test.mjs creates a new adapter and a new store in beforeEach: five tests cover focused actions and earlier snapshots, defaults per test, two independent stores, asynchronous hydration and a saved field that cannot replace an action (`npm run test:workspace`).

## Run

Copy the project into your React workspace (for example C:\react\zustand-workspace) and open it in VS Code. In one terminal run `npm ci`, then `npm run api` (the local catalog service on http://127.0.0.1:5191, in memory: a restart restores the four sample products). In a second terminal run `npm run dev` and open http://127.0.0.1:5190 (stop any other app using ports 5190 or 5191 first, and use the same 127.0.0.1 address throughout: localhost is a different browser-storage origin). Validate with `npm run lint` and `npm run build`.
