# Authorization & Ownership

The completed application is the exact source demonstrated in the video.

- Starter/shopfront-next: the ShopFront app as completed in the previous lecture.
- Support Files/shopfront-next: the local account fixtures (prisma/fixtures.ts), the request boundary helpers (lib/httpBoundary.ts) and the order note form (components/OrderNoteEditor.tsx), copied into the project in the video.
- Completed/shopfront-next: the app at the end of this lecture. Keep it for the next lecture.
- Not included: the private .env and Prisma's generated client folder (generated/), which you create as Run describes.

Order ownership checked inside the database operation: the schema links Customer.userId (optional, unique, cleared when its user is deleted) to the authentication User and adds Order.note, in an ownership migration created with migrate diff and applied with db:deploy; `npm run db:fixtures` links the synthetic accounts to customers C-1 and C-2 and adds Bob's order O-2001; lib/orderAccess.ts has AccessError, requireCurrentUser (401 without a session), getMyOrder (findFirst on the order id and the owner's user id: 404 for a missing order or another user's) and updateMyOrderNote (updateMany with the same conditions: exactly one row, otherwise 404); the private API route app/api/workshop/orders/[id]/route.ts (GET, and PATCH with an origin check and a note of at most 200 characters; private, no-store responses) and the page app/(store)/workshop/orders/[id]/page.tsx with the supplied note editor.

## Run

Work in C:\react\shopfront-next: continue your own working copy there, or copy this ZIP's Starter (to follow the video) or Completed shopfront-next folder there. No folder anywhere in the path may contain the & character, so never run npm inside the extracted section folder. Open the folder in VS Code. The ZIP leaves out the private .env file and Prisma's generated client (generated/): you create both below.

PostgreSQL must be running with the course role shopfront and its two databases, shopfront_dev (development) and shopfront_test (automated tests only), as set up in Setting the Environment: in SQL Shell, as the postgres administrator, `CREATE ROLE shopfront LOGIN;`, `\password shopfront` (a private password), `CREATE DATABASE shopfront_dev OWNER shopfront;` and `CREATE DATABASE shopfront_test OWNER shopfront;`. Reuse existing course databases; never drop or reset one.

Copy .env.example to .env (Git ignores it) and enter your own private values: in DATABASE_URL and DIRECT_URL (both shopfront_dev) and TEST_DATABASE_URL (shopfront_test) replace REPLACE_ME with the shopfront role's password, and 5432 with your PostgreSQL port if you chose another one. URL-encode special characters in that password (for example @ as %40, : as %3A, / as %2F, # as %23, % as %25), or they are read as parts of the connection string. Keep COURSE_ALLOW_WRITES=disabled in .env, in an .env.local left from the previous section, and in the terminal before you start Next (PowerShell: `$env:COURSE_ALLOW_WRITES="disabled"`; macOS/Linux: `export COURSE_ALLOW_WRITES=disabled`): a terminal value or .env.local takes priority over .env. Set BETTER_AUTH_URL=http://localhost:3000 and replace the BETTER_AUTH_SECRET placeholder with your own random secret, generated privately with `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"` (never share it or commit it). GITHUB_CLIENT_ID and GITHUB_CLIENT_SECRET stay optional (OAuth Sign-In; callback http://localhost:3000/api/auth/callback/github): leave them empty to hide the GitHub button. Keep the local mail values from .env.example (SMTP_HOST=127.0.0.1, SMTP_PORT=2525, SMTP_SECURE=false, empty SMTP_USER and SMTP_PASSWORD, an example.test MAIL_FROM).

Stop any other app using ports 3000, 5211, 2525 or 3041 first. In a first terminal run `npm ci` (the first installation needs registry access), then `npm run db:check`: it prints the connected database (shopfront_dev) and user (shopfront), never the password. Then run `npm run db:deploy` (applies the saved migrations to shopfront_dev; a repeated run reports none pending), `npm run db:generate` (writes Prisma's typed client into generated/; rerun it, and restart Next, after every schema change) and `npm run db:seed` (the sample customers, products and order; safe to repeat, and it restores the sample stock), then `npm run db:fixtures` (the synthetic local accounts alex@example.test and bob@example.test linked to customers C-1 and C-2, and Bob's order O-2001; a newly created fixture account gets the course-only password written in prisma/fixtures.ts, an existing account keeps its password). The seed and fixture scripts refuse any database other than the local shopfront_dev or shopfront_test. To open the app, run `npm run api` in a second terminal (the public catalog still reads its sample catalog API on http://127.0.0.1:5211) and `npm run mail` in a third (the local mail sink: SMTP on 127.0.0.1:2525 and a mailbox page at http://127.0.0.1:3041; it accepts only example.test recipients), then, in another terminal, `npm run dev -- --port 3000` and open http://localhost:3000 (the npm scripts bind 127.0.0.1; keep using localhost, the origin in BETTER_AUTH_URL: 127.0.0.1 is a different browser origin). `npm run check` checks the TypeScript code; restart Next after `npm run db:generate` or a change to .env. Stop each process with Ctrl+C when you finish.

## Try it

After `npm run db:fixtures`, restart Next and sign in on /workshop/account as alex@example.test (with the course-only fixture password from prisma/fixtures.ts, or the password the account already had). Open http://localhost:3000/workshop/orders/O-1001, edit the note, save and reload: the note is kept. Sign out and sign in as bob@example.test: /workshop/orders/O-1001 shows the not-found feedback instead of Alex's note, while /workshop/orders/O-2001 works. The direct request checks follow in Authentication Integration Tests.
