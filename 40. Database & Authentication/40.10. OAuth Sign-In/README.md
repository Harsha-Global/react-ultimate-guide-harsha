# OAuth Sign-In

The completed application is the exact source demonstrated in the video.

- Starter/shopfront-next: the ShopFront app as completed in the previous lecture.
- Completed/shopfront-next: the app at the end of this lecture. Keep it for the next lecture.
- Not included: the private .env and Prisma's generated client folder (generated/), which you create as Run describes.

An optional GitHub sign-in: .env.example gains empty GITHUB_CLIENT_ID and GITHUB_CLIENT_SECRET with the callback address; lib/auth.ts adds the GitHub social provider only when both private values exist; the account page passes only a githubEnabled boolean (never a credential) to AccountPanel, which shows Continue with GitHub (authClient.signIn.social with the github provider, with busy, error and connection-failure handling) in the signed-out view.

## Run

Work in C:\react\shopfront-next: continue your own working copy there, or copy this ZIP's Starter (to follow the video) or Completed shopfront-next folder there. No folder anywhere in the path may contain the & character, so never run npm inside the extracted section folder. Open the folder in VS Code. The ZIP leaves out the private .env file and Prisma's generated client (generated/): you create both below.

PostgreSQL must be running with the course role shopfront and its two databases, shopfront_dev (development) and shopfront_test (automated tests only), as set up in Setting the Environment: in SQL Shell, as the postgres administrator, `CREATE ROLE shopfront LOGIN;`, `\password shopfront` (a private password), `CREATE DATABASE shopfront_dev OWNER shopfront;` and `CREATE DATABASE shopfront_test OWNER shopfront;`. Reuse existing course databases; never drop or reset one.

Copy .env.example to .env (Git ignores it) and enter your own private values: in DATABASE_URL and DIRECT_URL (both shopfront_dev) and TEST_DATABASE_URL (shopfront_test) replace REPLACE_ME with the shopfront role's password, and 5432 with your PostgreSQL port if you chose another one. URL-encode special characters in that password (for example @ as %40, : as %3A, / as %2F, # as %23, % as %25), or they are read as parts of the connection string. Keep COURSE_ALLOW_WRITES=disabled in .env, in an .env.local left from the previous section, and in the terminal before you start Next (PowerShell: `$env:COURSE_ALLOW_WRITES="disabled"`; macOS/Linux: `export COURSE_ALLOW_WRITES=disabled`): a terminal value or .env.local takes priority over .env. Set BETTER_AUTH_URL=http://localhost:3000 and replace the BETTER_AUTH_SECRET placeholder with your own random secret, generated privately with `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"` (never share it or commit it). GITHUB_CLIENT_ID and GITHUB_CLIENT_SECRET are optional: left empty, the Continue with GitHub button stays hidden and password sign-in works as before; for GitHub sign-in, register an OAuth app with the callback http://localhost:3000/api/auth/callback/github (see Try it) and put its values only in .env, never in a NEXT_PUBLIC_ variable.

Stop any other app using ports 3000 or 5211 first. In a first terminal run `npm ci` (the first installation needs registry access), then `npm run db:check`: it prints the connected database (shopfront_dev) and user (shopfront), never the password. Then run `npm run db:deploy` (applies the saved migrations to shopfront_dev; a repeated run reports none pending), `npm run db:generate` (writes Prisma's typed client into generated/; rerun it, and restart Next, after every schema change) and `npm run db:seed` (the sample customers, products and order; safe to repeat, and it restores the sample stock). The seed script refuses any database other than the local shopfront_dev or shopfront_test. To open the app, run `npm run api` in a second terminal (the public catalog still reads its sample catalog API on http://127.0.0.1:5211), then, in another terminal, `npm run dev -- --port 3000` and open http://localhost:3000 (the npm scripts bind 127.0.0.1; keep using localhost, the origin in BETTER_AUTH_URL: 127.0.0.1 is a different browser origin). `npm run check` checks the TypeScript code; restart Next after `npm run db:generate` or a change to .env. Stop each process with Ctrl+C when you finish.

## Try it

Without GitHub values the button is hidden and the password form still works. To try GitHub, open GitHub's Settings, Developer settings, OAuth Apps and register a new application with the homepage URL http://localhost:3000 and the authorization callback URL http://localhost:3000/api/auth/callback/github; generate a client secret and put the client ID and secret only in .env. Restart Next, sign out on /workshop/account if a session remains, select Continue with GitHub, finish GitHub's sign-in and consent, and check that the returned account page shows the session in both views; reload, then sign out. A callback mismatch means the addresses differ: compare the origin exactly (127.0.0.1 is not localhost).
