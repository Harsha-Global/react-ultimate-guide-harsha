# Better Auth Setup

The completed application is the exact source demonstrated in the video.

- Starter/shopfront-next: the ShopFront app as completed in Server Data Access (Authentication Foundations, the lecture in between, changes no code).
- Completed/shopfront-next: the app at the end of this lecture. Keep it for the next lecture.
- Not included: the private .env and Prisma's generated client folder (generated/), which you create as Run describes.

The authentication service, before its visible form: better-auth and its schema tool installed with `npm install better-auth@1.7.7 --save-exact` and `npm install -D auth@1.7.7 --save-exact`; BETTER_AUTH_URL and BETTER_AUTH_SECRET in .env.example; lib/authOptions.ts (email and password sign-in with a 12-character minimum, a one-day session refreshed hourly, the cookie cache off, database-backed rate limiting); auth.schema.ts for the generator, and `npm run auth:generate` adding the User, Session, Account, Verification and RateLimit models to prisma/schema.prisma; an authentication migration created with `npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script --output ...` and applied with db:deploy; lib/auth.ts (server-only) with the Prisma adapter; and the catch-all route app/api/auth/[...all]/route.ts exporting the library's GET and POST handlers.

## Run

Work in C:\react\shopfront-next: continue your own working copy there, or copy this ZIP's Starter (to follow the video) or Completed shopfront-next folder there. No folder anywhere in the path may contain the & character, so never run npm inside the extracted section folder. Open the folder in VS Code. The ZIP leaves out the private .env file and Prisma's generated client (generated/): you create both below.

PostgreSQL must be running with the course role shopfront and its two databases, shopfront_dev (development) and shopfront_test (automated tests only), as set up in Setting the Environment: in SQL Shell, as the postgres administrator, `CREATE ROLE shopfront LOGIN;`, `\password shopfront` (a private password), `CREATE DATABASE shopfront_dev OWNER shopfront;` and `CREATE DATABASE shopfront_test OWNER shopfront;`. Reuse existing course databases; never drop or reset one.

Copy .env.example to .env (Git ignores it) and enter your own private values: in DATABASE_URL and DIRECT_URL (both shopfront_dev) and TEST_DATABASE_URL (shopfront_test) replace REPLACE_ME with the shopfront role's password, and 5432 with your PostgreSQL port if you chose another one. URL-encode special characters in that password (for example @ as %40, : as %3A, / as %2F, # as %23, % as %25), or they are read as parts of the connection string. Keep COURSE_ALLOW_WRITES=disabled in .env, in an .env.local left from the previous section, and in the terminal before you start Next (PowerShell: `$env:COURSE_ALLOW_WRITES="disabled"`; macOS/Linux: `export COURSE_ALLOW_WRITES=disabled`): a terminal value or .env.local takes priority over .env. Set BETTER_AUTH_URL=http://localhost:3000 and replace the BETTER_AUTH_SECRET placeholder with your own random secret, generated privately with `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"` (never share it or commit it).

Stop any other app using ports 3000 or 5211 first. In a first terminal run `npm ci` (the first installation needs registry access), then `npm run db:check`: it prints the connected database (shopfront_dev) and user (shopfront), never the password. Then run `npm run db:deploy` (applies the saved migrations to shopfront_dev; a repeated run reports none pending), `npm run db:generate` (writes Prisma's typed client into generated/; rerun it, and restart Next, after every schema change) and `npm run db:seed` (the sample customers, products and order; safe to repeat, and it restores the sample stock). The seed script refuses any database other than the local shopfront_dev or shopfront_test. `npm run auth:generate` (run in the video) writes the authentication models into prisma/schema.prisma from auth.schema.ts; the Completed schema already contains them, so rerun it only after changing lib/authOptions.ts, followed by a new reviewed migration. To open the app, run `npm run api` in a second terminal (the public catalog still reads its sample catalog API on http://127.0.0.1:5211), then, in another terminal, `npm run dev -- --port 3000` and open http://localhost:3000 (the npm scripts bind 127.0.0.1; keep using localhost, the origin in BETTER_AUTH_URL: 127.0.0.1 is a different browser origin). `npm run check` checks the TypeScript code; restart Next after `npm run db:generate` or a change to .env. Stop each process with Ctrl+C when you finish.

## Try it

With the authentication values in .env, `npm run db:deploy` applies the authentication migration and `npm run db:generate` updates the client; `npm run check` passes. In SQL Shell or pgAdmin, shopfront_dev now has the authentication tables (User, Session, Account, Verification, RateLimit) beside Customer, Product, Order and OrderItem, and the sample rows are unchanged. Restart Next: the store still works, and the account form follows in Sessions & Account Form.
