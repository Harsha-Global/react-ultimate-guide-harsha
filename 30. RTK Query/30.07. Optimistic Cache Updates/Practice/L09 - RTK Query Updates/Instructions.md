Add onQueryStarted to updateOrder. Patch only the existing getOrder cache entry whose argument exactly matches the edited order ID. Show the requested status immediately, keep the server version unchanged until the response, and reconcile subscribed lists/details with the server after completion. Restore the earlier status when an isolated mutation is rejected. Before undoing, also require the original session, the submitted version and the optimistic status to remain current. For overlapping edits of the same order or a newer result, let invalidation/refetch recover instead of undoing a patch that could erase another edit. Do not manufacture a missing cache entry or mutate a response object outside the cache callback. Use the supplied mutation-group helper from the lecture if useful.
