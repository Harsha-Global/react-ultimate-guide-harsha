R03 — Sample response

1. The public catalog may use a shared server cache when its contents are the same for every visitor. A private account summary must be read under the authenticated request and a correctly isolated data policy; it must never enter an unscoped public cache. A five-minute lifetime limits freshness, not who can receive the stored result.

2. After validation and authorization, wait for the API to accept the write. Expire the exact tag attached by the reader with updateTag in the Server Action, then refresh the current interface. A mismatched tag leaves the relevant entry unchanged. revalidateTag(tag, "max") marks a tagged result stale for its revalidation policy; it does not itself repaint the current page. refresh requests new server output and does not by itself establish a data-invalidating policy.

3. Warm the catalog and record its stock and revision. Save a different stock value before natural expiry can hide the defect, then compare the confirmed API result, cached card and category snapshot. Reject another edit and verify that the previous confirmed value remains. Check direct reload, navigation and history. Inspect TanStack Query separately because its browser cache has its own key and stale-time policy; a Next data tag does not directly clear it.
