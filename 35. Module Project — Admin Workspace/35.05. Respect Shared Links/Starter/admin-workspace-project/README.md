# Admin Workspace — an explicit saved view snapshot

The Admin Workspace project can save one browser-local snapshot of the active view and apply it later. src/savedView.ts defines savedViewSchema with Zod (q: a string of at most 60 characters; sort: "", name, category, priceMinor or stock; dir: asc or desc; size: 2 or 4), the inferred SavedView type, readSavedView (unknown input through safeParse: the parsed data or null) and viewUpdate (a valid snapshot plus page 1). src/savedViewStore.ts creates the store with createSavedViewStore(storage): persist under the key admin-saved-view, version 1, the received storage adapter, partialize keeping only saved, and a merge that validates the stored value and keeps the real save/clear actions; useSavedViewStore is the browser instance. src/useCatalogView.ts derives currentView from the URL values and adds applyView (setView(viewUpdate(saved)) with push history). src/components/SavedViewBar.tsx shows the saved choices, Save (or Replace) this view, Apply saved view and Forget saved view (disabled without a snapshot); src/App.tsx renders it below the search card. Reloading restores the stored snapshot into the store, not the URL.

## Run

Copy the project into your React workspace (for example C:\react\admin-workspace-project) and open it in VS Code. In one terminal run `npm ci`, then `npm run api` (the local catalog service on http://127.0.0.1:5191, in memory: a restart restores the four sample products). In a second terminal run `npm run dev` and open http://127.0.0.1:5190 (stop any other app using ports 5190 or 5191 first, and use the same 127.0.0.1 address throughout: localhost is a different browser-storage origin). Validate with `npm run lint` and `npm run build`.
