Use the completed local production-build rehearsal when provider prerequisites are not available.
1. Stop other Next/sample API processes for this project. Keep PostgreSQL running.
2. Set DEPLOYMENT_KIND=local, PORT=3000, SITE_URL=http://localhost:3000 and
   BETTER_AUTH_URL=http://localhost:3000 in your private .env. Keep the random auth secret stable.
3. Run npm run release:check, npm run db:deploy, then npm run release:build.
4. Run npm run release:start. This owns both Next and the read-only catalog sample API.
5. Keep npm run mail, npm run storage and npm run jobs in their own terminals for local flows.
   Set the Inngest dev registration URL to the same Next origin/port. Use Stripe CLI forwarding
   only with your sandbox and the exact local /api/stripe/webhook endpoint.
6. Open the configured origin; verify the account, private order, direct routes and recovery.
7. Stop the release launcher with Control+C; it stops only its own children.

Chosen rehearsal services: Render Node + Render Postgres, Backblaze B2 private S3
storage, Resend SMTP, Stripe sandbox, Inngest Cloud, and the Sentry project created
in Controlled Error Capture. These choices fit the existing adapters; do not replace application code
with a provider wizard. Use separate practice accounts/resources. Check current
eligibility and limits before creation; do not accept a paid upgrade or add a card
as an unannounced course prerequisite. No hosted run is established by this guide.

Build: npm ci && npm run release:build

2. Create the database before migrating or deploying the completed application.

3. Create private object storage and its application credential.
At backblaze.com, sign up/sign in to a separate B2 Cloud Storage account and finish
its verification. Under B2 Cloud Storage > Buckets > Create a Bucket, enter a
unique practice name and choose Private. Retain a private bucket throughout.
Copy its displayed S3 endpoint and region, not a public download URL.
Under Application Keys > Add a New Application Key, choose this bucket and Read
and Write. Use no filename-prefix restriction: this app uses both quarantine/ and
orders/ keys. Save the shown keyID and one-time applicationKey privately.
Map only this restricted application key into Render:
S3_ENDPOINT=https://<the displayed S3 endpoint>
S3_REGION=<the endpoint's actual region>
S3_BUCKET=<the private bucket name>
S3_ACCESS_KEY=<keyID>
S3_SECRET_KEY=<applicationKey>
Do not use the local SeaweedFS credentials or a master key on the host.

Configure CORS for this new bucket with the one-time command below. Backblaze's
PutBucketCors needs writeBuckets; the bucket-restricted app key cannot do it.
In this isolated practice account, create a second, temporary application key with
All buckets and Read and Write. It is only for this setup operation. Do not use a
master key. Set a short expiration, and revoke it after the configuration check.
Run in the already installed project directory in a separate PowerShell terminal.
Read-Host prevents secrets appearing as literal commands/history. Never display
the environment, print the credential or capture a revealed provider key.

$env:B2_SETUP_ENDPOINT = Read-Host 'S3 HTTPS endpoint'
$env:B2_SETUP_REGION = Read-Host 'S3 region'
$env:B2_SETUP_BUCKET = Read-Host 'New private bucket name'
$env:B2_SETUP_ORIGIN = Read-Host 'Exact assigned HTTPS application origin'
$env:B2_SETUP_KEY_ID = Read-Host 'Temporary setup key ID'
$setupSecret = Read-Host 'Temporary setup application key' -AsSecureString
$env:B2_SETUP_SECRET = [System.Net.NetworkCredential]::new('', $setupSecret).Password
@'
import { S3Client, PutBucketCorsCommand, GetBucketCorsCommand } from '@aws-sdk/client-s3';
try {
  const origin = new URL(process.env.B2_SETUP_ORIGIN);
  const endpoint = new URL(process.env.B2_SETUP_ENDPOINT);
  if (origin.protocol !== 'https:' || origin.pathname !== '/' || origin.search || origin.hash || origin.username || origin.password || endpoint.protocol !== 'https:') throw new Error();
  const client = new S3Client({
    endpoint: endpoint.href, region: process.env.B2_SETUP_REGION, forcePathStyle: true,
    credentials: { accessKeyId: process.env.B2_SETUP_KEY_ID, secretAccessKey: process.env.B2_SETUP_SECRET },
    requestChecksumCalculation: 'WHEN_REQUIRED', maxAttempts: 2,
    requestHandler: { connectionTimeout: 2000, requestTimeout: 8000 },
  });
  const Bucket = process.env.B2_SETUP_BUCKET;
  await client.send(new PutBucketCorsCommand({ Bucket, CORSConfiguration: { CORSRules: [{
    AllowedOrigins: [origin.origin], AllowedMethods: ['PUT'],
    AllowedHeaders: ['content-type'], MaxAgeSeconds: 300,
  }] } }));
  const result = await client.send(new GetBucketCorsCommand({ Bucket }));
  if (result.CORSRules?.length !== 1 || result.CORSRules[0].AllowedOrigins?.[0] !== origin.origin || result.CORSRules[0].AllowedMethods?.[0] !== 'PUT') throw new Error();
  console.log('Exact-origin browser upload rule saved and read back.');
  client.destroy();
} catch { console.error('CORS setup failed. Check the endpoint, region, bucket and setup-key permissions privately.'); process.exitCode = 1; }
'@ | node --input-type=module
Remove-Item Env:B2_SETUP_* -ErrorAction SilentlyContinue
Remove-Variable setupSecret -ErrorAction SilentlyContinue

Delete the temporary key in Backblaze's Application Keys page. Retain only the

4. Configure mail with Resend.
At resend.com, create/verify a practice account whose mailbox you can open. API
Keys > Create API Key: name it shopfront-preview and choose Sending access. Save
its one-time value privately. Set these Render environment variables:
SMTP_HOST=smtp.resend.com
SMTP_PORT=2587
SMTP_SECURE=false
SMTP_USER=resend
SMTP_PASSWORD=<Resend sending API key>
MAIL_FROM=ShopFront <onboarding@resend.dev>
SMTP_SECURE=false selects STARTTLS, not unencrypted delivery: lib/mail.ts already
requires TLS for nonlocal hosts. Render Free blocks 25/465/587; use 2587 here.
The resend.dev sender is for testing only and can send to the Resend account's
own email address. Use that exact address for the hosted app sign-up and recovery
check. Do not attempt delivery to the local alex@example.test fixture or another
student's mailbox. For other recipients, Domains > Add Domain requires a domain
you control, its displayed DNS verification records and Verified status; then use
an address on that domain as MAIL_FROM. That is not required for this one-mailbox
rehearsal. No domain purchase is assumed. Sending-limit/account-approval failures
remain real blockers, not successful verification.
